Methodology

Technical documentation describing how FBI Epstein documents were processed, analyzed, and presented in this explorer.

Data Sources

This explorer presents documents from official government FOIA releases:

  • FBI FOIA Vault: 7 volumes of FBI investigative records released under Freedom of Information Act requests
  • House Oversight Committee: Documents released by congressional oversight activities
  • Court Records: Flight logs, contact books, and other materials released in federal court proceedings (US v. Maxwell)

All source documents are public domain government records. No private or sealed materials are included.

Processing Pipeline

1. OCR Text Extraction

Documents were processed using multiple OCR engines to maximize accuracy:

  • Primary: AWS Textract for structured documents with tables and forms
  • Fallback: Surya OCR for handwritten and low-quality scans
  • Average OCR confidence: 85% (varies by document quality)

2. Entity Extraction

Named entities (people, locations, organizations) were extracted using:

  • Model: Claude 3 Haiku via AWS Bedrock
  • Prompt Engineering: Custom prompts optimized for legal/investigative documents
  • Post-processing: Deduplication using 85% fuzzy matching with blocking by entity type

3. Vector Embeddings

Semantic search is powered by document embeddings:

  • Model: nomic-embed-text (768 dimensions)
  • Chunking: 512 tokens with 50-token overlap
  • Storage: Milvus vector database with partition-based optimization

4. Dimensionality Reduction

UMAP (Uniform Manifold Approximation and Projection) is used to visualize high-dimensional embeddings in 2D space, revealing document clusters and thematic groupings.

Victim Protection Policy

Important: This project respects the privacy and dignity of victims. Known victim names that appear in source documents are preserved as redacted by the releasing agencies: [VICTIM - NAME REDACTED]

Our approach to victim protection:

  • Source redactions from FBI/DOJ are maintained and not reversed
  • Entity extraction filters exclude known victim-associated patterns
  • No victim identification or deanonymization is performed
  • Victim-related metadata in entity profiles shows redaction placeholder only

Technical Architecture

  • Frontend: Static HTML/CSS/JavaScript hosted on GitHub Pages
  • Data: JSON files for entities, documents, and profiles
  • Visualizations: Plotly.js, vis.js, D3.js, Cosmograph (WebGL)
  • Network Analysis: NetworkX with Louvain community detection
  • Search: Client-side full-text search with optional RAG API integration
  • Dataset Hosting: HuggingFace Datasets for large files

Limitations & Disclaimers

  • OCR Accuracy: Text extraction varies by document quality. Handwritten notes, faxes, and degraded copies may contain errors.
  • Entity Extraction: AI-based extraction has false positives (incorrectly identified entities) and false negatives (missed entities). Results should be verified against source documents.
  • Generated Profiles: Some entity profiles are algorithmically generated and may contain uncertainties or incomplete information.
  • Connections: Entity relationship strengths are based on document co-occurrence, not verified real-world relationships.
  • Not Legal Evidence: This tool is for research and journalism purposes. Document contents should be independently verified for any legal or formal use.
